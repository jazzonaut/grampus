# Execution efficiency

The adaptive candidate workflow is described in [WORKFLOW.md](WORKFLOW.md). Implementers use native
tools to inspect, edit, install, format, test and debug. File suggestions, formatter commands and
diagnostic grammars are not execution permissions. Grampus no longer inserts a scoped finishing
cycle after a native turn.

Ordinary debugging stays inside implementation. A progress message continues the same execution;
only an explicit candidate enters controller verification. Readiness, validation and ordered
acceptance run against the submitted artifact before independent review. Required coverage is not
replaced by agent claims. Task-wide spending, context rotation, repair allowances, process ownership,
recovery and verified local delivery remain durable controller responsibilities.

The dashboard and reports retain workflow and execution-phase timing. Native command activity comes
from provider observations rather than a controller receipt for each shell command. Readiness
concurrency remains explicit and bounded. No measured speed-up is claimed.

**Planned:** compare the same real task from the same base with the same model through adaptive Grampus
and a direct native agent. Measure accepted completion, human interventions, elapsed time and usage.
A successful real-project pilot is required before treating the flow as validated in practice.
